# Lessons are annotated without being modified: an iframe, and highlights that are not DOM

A Lesson is a self-contained document `/teach` wrote, loading `../assets/*.css` and `../assets/*.js` and linking sideways to its siblings. Nothing the app builds may change that, which rules out the obvious approach: rendering Lesson HTML into React with `dangerouslySetInnerHTML` does not execute script tags, so `fretboard.js` and `bitbox.js` go dead, and the Lesson's stylesheet collides with the app's.

So the Lesson is served raw as it always was and wrapped in a same-origin `<iframe>` on an app page. The annotation panel and the Ask thread live in the React parent; `iframe.contentWindow.getSelection()` reaches across because the origin is shared. Highlights are painted with the CSS Custom Highlight API — `Range` objects registered in `CSS.highlights` and styled through `::highlight()` — which puts no marks in the document at all. Rejected injecting `<mark>` spans: it mutates a file the app does not own, reflows the page, and can land inside markup a Lesson's own script is reading. Rejected injecting a script tag into the served HTML: it keeps one document at the price of a second, hand-written UI stack beside React.

An Anchor is the W3C Web Annotation pair — a TextQuoteSelector (the quote plus the words either side) and a TextPositionSelector (character offsets) — resolved quote-first on every load, with the position as the cheap hint. Rejected quote-only, which cannot survive two identical passages, and rejected DOM paths, which are defeated by exactly the edit this project produces: `/teach` regenerating a Lesson wholesale. When both fail the Annotation is shown unanchored rather than dropped; a note the learner wrote is never lost to a Lesson they did not edit.
